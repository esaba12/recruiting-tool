# Phase 7 — UI Design Contract

> Visual and interaction contract for the industrial/control-panel reskin of every screen (including low-traffic ones), motion package migration, and instrument-panel stat tiles. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Aesthetic direction (explicit, locked from Phase 1):** Industrial / control-panel. Cool gunmetal `ink` scale, safety-orange `accent`, contrast-validated `success`/`warning`/`danger` ramps. Dark-IDE-adjacent (Nord/Monokai-adjacent), dense instrument-panel visual language. **This phase extends that aesthetic through a shape-system tightening (border-radius reduction, soft shadows → borders) applied app-wide, plus motion and new instrument-panel stat tiles.**

**Hard constraint honored:** Token *names* and *values* inherited from Phase 1 (no new tokens, no value changes). This phase introduces **new shape-system defaults** (radius, border, shadow treatment) applied to shared `ui/` primitives so every consumer inherits them, matching Phase 1's precedent.

**Scope:** `app/src/components/` (all screens, including low-traffic ones), `app/src/lib/` (motion hooks, tile data aggregation), `app/src/index.css` (no new tokens, but shape system documented), `app/package.json` (dependency swap: `framer-motion` → `motion`).

## Shape System Tightening (VIS-01 / D-01)

**The core "sharp edges, instrument-panel" visual change:** Reduce corner radius and swap soft shadows for visible borders on all primary containers, applied once to shared `ui/` primitives so every consumer inherits.

### Radius Changes

| Component | Old | New | Rationale |
|-----------|-----|-----|-----------|
| Card | `rounded-xl` (16px) | `rounded-md` (6px) | Flatter, sharper industrial read |
| SidePanel | `rounded-2xl` (24px) | `rounded-md` (6px) | Consistent with Card; primary panel |
| Modal | `rounded-2xl` (24px) | `rounded-md` (6px) | Consistent with Card; primary panel |
| Section | `rounded-lg` (8px) or none | `rounded-md` (6px) | Subtle, consistent secondary container |
| Small chips/pills (Button variants, Tags) | `rounded-full` (999px) | Keep `rounded-full` for genuinely circular elements; `rounded-sm` (4px) for pill-shaped elements | Preserve circular avatars/dots; tighten pill shapes |

### Shadow → Border Swap

Replace all `shadow-sm`, `shadow-md`, `shadow-lg`, `shadow-xl`, `shadow-2xl` with a **1px solid border** using the color-coded scheme below. This is a structural change to the primitive CSS, not a per-call-site edit.

| Component | Old Shadow | New Border | Hex Value | Rationale |
|-----------|-----------|-----------|-----------|-----------|
| Card (primary raised panel) | `shadow-sm` / `shadow-md` | `1px solid border-ink-300` | `#a2a7af` | Bezel-like depth cue for primary cards |
| SidePanel (primary panel) | `shadow-md` / `shadow-lg` | `1px solid border-ink-300` | `#a2a7af` | Consistent with Card; strong edge definition |
| Modal (primary overlay) | `shadow-2xl` | `1px solid border-ink-300` | `#a2a7af` | Flat, bordered overlay against dark backdrop |
| Section (secondary grouping) | `shadow-sm` or none | `1px solid border-ink-200` | `#c7cbd0` | Subtle grouping line; lighter than primary |

**No background changes:** Card/SidePanel/Modal backgrounds remain `bg-white` (unchanged from Phase 1) — against the new cooler canvas, white reads as "raised panel" as intended.

**Exception — keep existing behaviors:** Button variant states (hover/active/focus), focus rings, and existing CSS animations on transitions stay intact. Only the drop-shadow styling on containers is replaced with borders.

Verify the existing animations still fire correctly on local dev after the import swap.

### New Motion Additions (D-04)

Add staggered-reveal motion to two locations (both using `motion/react`):

#### 1. Today's Section List Stagger

**File: `components/TodayTab.jsx`**

**Location:** The `ActivitySection` function (lines ~319–393) and all other `Section` components rendered in TodayTab's final list. Already has precedent from Phase 6's ported Overview charts which included "staggered KPI-card reveal on mount."

**Behavior:** When `TodayTab` mounts, each `<Section>` container enters with a staggered fade-in (offset by ~100ms per section), creating the visual rhythm of a control-panel "powering up." This is a **mount-time animation only** — subsequent navigation to Today does not re-trigger unless there's new data.

**Implementation hook:** Wrap the section list in `<motion.div>` with `AnimatePresence` and apply `initial={{ opacity: 0, y: 8 }}` / `animate={{ opacity: 1, y: 0 }}` per section, with `transition={{ delay: index * 0.1 }}` to stagger them. Or use Framer Motion's / `motion`'s built-in stagger pattern (`transition={{ staggerChildren: 0.1 }}`).

#### 2. Instrument-Panel Stat Tile Row Stagger (STAT-01, see below)

**File: `components/TodayTab.jsx`**

**Location:** New 3-tile row (D-06) at the top of the existing `ActivitySection`.

**Behavior:** Same stagger pattern as above — tiles enter in sequence on `ActivitySection` mount, ~100ms apart. This reinforces the "dashboard startup" aesthetic at the page's most prominent point.

### Exclusions (D-05 — Must Remain True)

**These must NOT receive motion treatment this phase:**

1. **`components/NetworkGraphTab.jsx`** — The `react-force-graph-2d` canvas is not DOM-animatable the way div/SVG elements are. Confirm this file has zero `framer-motion` or `motion` imports before and after this phase (it currently has zero — do not add any).
2. **`components/charts/BarChart.jsx`, `DonutChart.jsx`, `TrendChart.jsx`** — Recharts internals handle their own chart animations (bar transitions, slice reveals, line draws). Do NOT wrap individual `<Bar>`, `<Pie>`, `<Line>`, etc. components in `motion` components. Let Recharts manage its own timing.

**Verification:** After merging this phase, run `grep -r "react-force-graph\|framer-motion\|motion/react" app/src/components/NetworkGraphTab.jsx app/src/components/charts/` to confirm zero matches on the graph file and zero *new* motion wrapping on individual Recharts elements.

## Instrument-Panel Stat Tiles (STAT-01 / D-06, D-07, D-08)

### Overview

A new **3-tile row** inserted at the top of `TodayTab.jsx`'s existing `ActivitySection`, summarizing key job-search metrics as gauge-like mono readouts. Tiles are **additive** above the existing Funnel/Donut/Trend charts (not a replacement), reusing the existing Recharts data pipelines.

### Tile 1: Funnel Summary

**Title:** "Funnel" or "Progress"

**Data source:** `ActivitySection`'s existing funnel chart data (Applications by Stage). Computed from the live `apps` array passed into `ActivitySection`.

**Readout format:**

```
Funnel
━━━━━━━
Applied
<Mono>23</Mono>  ← count of all `stage` Applied + beyond
```

Or if showing conversion: `3/5 stages reached` or `Applied: 23 (18% of all)`

**Style:** 
- Title: `text-xs font-semibold text-ink-600` (Label weight/size from Phase 1)
- Numeral: `<Mono>23</Mono>` (IBM Plex Mono, 12px, regular, tabular-nums, tracking-wide)
- Tile container: `rounded-md border-1 border-ink-300 bg-white p-4` (new shape system from D-01)

### Tile 2: Days-to-Deadline Countdown

**Title:** "Next Deadline"

**Data source:** Job Boards' existing `rec_job_deadlines` localStorage cache (populated by `useJobDeadlines.js`). Derived by:
1. Scan the live `apps` (from Pipeline tab) for entries in Needs-Review or Applying stages that carry a `Source Repo` and match a Job Boards application by Company+Role.
2. Cross-reference each `Source Repo` against the deadlines cache (`rec_job_deadlines[<sourceRepo>]`).
3. Find the single soonest confirmed deadline across all matched jobs.
4. Calculate days until that deadline using `daysUntil()` from `lib/deadlines.js` (existing function).

**Fail-soft behavior:** If no confirmed deadline exists in the cache or no Pipeline apps have Source Repo metadata:
- Show: "No known deadlines" (neutral, not an error state)
- OR omit the tile entirely
- Never show a placeholder/fake countdown

**Readout format:**

```
Next Deadline
━━━━━━━━━━━━━━
Closes in
<Mono>12 days</Mono>  ← or "12d" if space-constrained
```

Or for multiple deadlines: show top 2–3 in a stacked layout, or just the soonest.

**Style:** Same as Tile 1. Optional: a thin tick-mark/progress-bar visual at the bottom of the tile indicating "days remaining / typical 30-day posting window" as a segmented fill or small horizontal indicator (e.g. a `<div className="h-1 bg-gradient-to-r from-danger-500 to-warning-500" />` at the bottom, filled proportionally).

### Tile 3: Activity Sparkline

**Title:** "Activity" or "Interactions"

**Data source:** `ActivitySection`'s existing `TrendChart` data (trailing 10-week interaction counts, computed by `getActivityData()` in `TodayTab.jsx`). The full `TrendChart` stays below this tile as the detailed view — this tile shows a **compressed summary**.

**Readout format:**

Option A (compact inline sparkline):
```
Activity
━━━━━━━
<Mono>27</Mono>  ← total interactions this week or trailing 10 weeks
⬡⬡⬡⬡◻◻ ← micro sparkline (6 boxes, last N weeks)
```

Option B (single metric):
```
Activity
━━━━━━━
This week
<Mono>3</Mono> interactions
```

**Style:** Same as Tile 1–2. Sparkline: use a compact Recharts `<BarChart>` (existing component) sized down to ~160px width × 40px height, or a CSS-based bar-graph (6 columns, each representing a week, filled proportionally).

### Tile Row Layout

**Grid:** 3 columns on desktop (equal width, e.g., `grid grid-cols-3 gap-4`), wrap to 2 columns on tablet, stack vertically on mobile.

**Container:**
- Padding: `p-4` or `p-6` (consistent with Section content padding)
- Background: `bg-white` (matches card surfaces)
- Margin: Inserted at line ~356 in `TodayTab.jsx`, inside the existing `<Section title="Activity">` wrapper, **above** the existing `ActivitySection` chart JSX
- Motion: Each tile inherits the stagger animation from the parent Section (see Motion section above)

### Integration with Existing Charts

The full-size Funnel/Donut/Trend charts that currently render in `ActivitySection` stay **unchanged** and stay **below** the new tile row. The tiles are a "dashboard glance" summary; the charts are the "detailed exploration" view. Users see both.
