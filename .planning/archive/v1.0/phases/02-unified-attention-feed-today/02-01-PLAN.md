<objective>
Build the three prerequisite, purely-additive pieces the rest of Phase 2 depends on, none of which change any user-visible behavior on their own: (1) `app/src/lib/attention.js`, a derivation module extracting `ActionsTab.jsx`'s inline filter/sort computations into named, reusable exports (per D-06 — this consolidates what STATE.md flagged as 3 independent duplicate copies of the same overdue/stale logic across `ActionsTab.jsx`, `OverviewTab.jsx`, and `App.jsx`); (2) an additive `today: Gauge` entry in `lib/icons.js`'s `NAV_ICON` map (per D-03's locked nav-icon choice); (3) a chrome refactor of `TimelineFindsPanel.jsx` so it visually matches the other 8 attention-feed sections' `Section` card convention instead of its current bespoke gradient/accordion header, with a new `onPendingChange` callback so a future parent can track its live pending count.

This plan deliberately does NOT touch `Sidebar.jsx`'s `NAV_ITEMS`, `App.jsx`, or remove anything from `NAV_ICON` — those cutover edits are sequenced into Plan 02-03, after `TodayTab.jsx` (Plan 02-02) fully exists and works, so no wave boundary in this phase ever has the `today` nav item reachable-but-broken or the `actions` nav item unreachable-but-still-imported.

Purpose: every later plan in this phase imports from `attention.js` or mounts the refactored `TimelineFindsPanel.jsx` — landing them first, in isolation, with zero behavior change to any currently-shipped surface, means Plan 02-02 can build `TodayTab.jsx` against stable, already-verified interfaces.
Output: `app/src/lib/attention.js` (new), `app/src/lib/icons.js` (additive edit), `app/src/components/TimelineFindsPanel.jsx` (chrome refactor, still mounted from `CalendarTab.jsx` unchanged until Plan 02-03).
</objective>
