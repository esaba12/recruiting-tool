<objective>
Close the still-open ATTN-01/Truth-1 gap 02-VERIFICATION.md's second pass reported (re-scoped after Plan 02-05 fixed the original staleness bug): `TodayTab.jsx`'s `allEmpty` early-return doesn't just decide page content — it decides whether `TimelineFindsPanel` mounts at all, and `TimelineFindsPanel` is currently the only place in the app that ever calls `findTimelineEvents()` (the daily AI scan). Once a user reaches a genuinely all-caught-up state, the panel never mounts, so the scan that would discover new calendar-worthy dates from fresh call notes/application updates/interactions can never run again — on that visit or any future one — with no manual escape hatch reachable in that state either (02-REVIEW.md's CR-01, new numbering).

Both of Plan 02-05's earlier two options (relabeled by 02-REVIEW.md as "Option A"/"Option B") were considered again here. Option A (always-mount `TimelineFindsPanel`, rescope `allEmpty` to the other 8 categories) is explicitly rejected a second time — it was already rejected once in Plan 02-05 for contradicting `02-UI-SPEC.md`'s "if all 9 arrays are empty, render one page-level EmptyState in place of the stack" contract (line ~142), and that contract has not changed. This plan implements Option B, extended to its natural conclusion: the entire Timeline Finds data lifecycle (the daily-scan trigger, `meta`/`pending`/`running`/`error` state, and the `scan`/`dismiss`/`updateField`/`approve` operations) is extracted out of `TimelineFindsPanel.jsx` into a new hook, `app/src/lib/useTimelineFinds.js`. `TodayTab.jsx` calls this hook unconditionally, grouped with its other `useState` calls, well above the `allEmpty` computation and its early-return — so the hook's internal `useEffect` (React hook execution is independent of what JSX a component ultimately returns) always runs once per `TodayTab` mount, regardless of whether `TodayTab` ends up rendering the full section stack or the page-level `EmptyState`. `TimelineFindsPanel.jsx` becomes a pure presentational component, receiving `pending`/`running`/`error`/`meta` and the four operation callbacks as props; its own JSX, styling, and click targets are otherwise unchanged, so it still only mounts when `!isDemoMode` and `allEmpty` is false — the section chrome that would regress the UI-SPEC's all-9-arrays contract by rendering nested inside an already-collapsed stack is never introduced.

This design simultaneously satisfies both hard constraints from 02-VERIFICATION.md's gap: (1) the daily scan (and its `meta.lastCheck`/hash-skip bookkeeping) can now run once/day even in the genuinely-caught-up state — no permanent lockout — because its trigger lives in a component (`TodayTab`) that always mounts whenever the Today tab is open, not in a component (`TimelineFindsPanel`) that only conditionally mounts; and (2) the page-level `EmptyState` contract is untouched — `TimelineFindsPanel`'s mount condition, and therefore whether its own internal "Nothing pending" chrome can ever render nested in the stack, is byte-identical to before this plan. The one accepted trade-off, per this gap-closure's own guidance: the manual "↻ Rescan" button (which lives inside `TimelineFindsPanel`, unchanged) remains unreachable in the exact all-caught-up state, same as before — acceptable because the automatic once-daily scan no longer depends on that state at all, so the primary lockout this gap describes is closed without needing a new UI affordance.
