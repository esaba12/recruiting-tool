## Hard constraints for this plan

1. **This plan changes zero source files.** If a gate fails, do not fix it here — record the failure, stop, and report it so gap closure can be planned properly. A sweep plan that quietly patches what it is auditing is not evidence.
2. **The base for every diff is `0c19dac`** — the last commit before any Phase 6 source change. Confirm it before use: its subject records the Phase 6 UI-SPEC session. The plan-creation commit that landed between it and this plan touched only `.planning/`, so scoping diffs to `app/` keeps the base valid.
3. **Do not run the deep-link audit by reading code and asserting it looks fine.** The gates below are byte-level diffs for a reason: Pitfall 3's failure mode produces no error, no warning, and no visible symptom on a first click.
4. **Live-render checks are staged, not run inline.** Phase 5 established that this repo's dev server cannot boot in an isolated worktree — the Supabase client throws before React mounts when `.env` is absent — and `workflow.human_verify_mode` is `end-of-phase`. An inline render failing on a missing `.env` would be a false negative.

## Task ordering rationale

Task 1 audits NAV-03 first, while nothing else is in flight, so the evidence is unambiguous. Task 2 then re-runs every other gate against the merged tree and writes the combined record.
