# Phase 6 — UI Design Contract

> Visual and interaction contract for Navigation Consolidation Complete. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Aesthetic direction:** Industrial / control-panel (unchanged, locked by PROJECT.md and Phase 1's `01-UI-SPEC.md`). This phase introduces **zero new visual-hierarchy decisions** — per `06-RESEARCH.md`'s framing, it is "subtractive (delete a file, shrink two arrays) and additive-by-composition (reuse `Section`, add one button using an existing icon and an existing callback)." The only genuinely new pixels in scope are (a) one `Section`-wrapped charts block appended to `TodayTab.jsx`, built entirely from `OverviewTab.jsx`'s existing chart markup ported verbatim, and (b) one new Settings button reusing the exact active/inactive styling already established by `NAV_ITEMS` buttons and the existing footer button group. This UI-SPEC should be read against that narrow scope, the same way `05-UI-SPEC.md` was read against its shell-only scope.

**Hard constraint honored:** `BarChartWrapper`/`DonutChart`/`TrendChart` (imported from `charts/`) and their underlying computation logic (`funnelData`, `conversions`, `donutData`, `trendData`) get **zero visual or logic changes** beyond a straight relocation from `OverviewTab.jsx` into `TodayTab.jsx` (per D-01/RESEARCH.md Pattern 3 — "computed exactly as OverviewTab.jsx did, ported verbatim"). Nothing in this contract authorizes restyling the charts, the Section shell, or the existing nav/footer button patterns.

## Spacing Scale

Declared values (must be multiples of 4) — unchanged from `01-UI-SPEC.md`, restated for reference:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**This phase's specific spacing decisions:**

- **Merged charts Section** (`TodayTab.jsx`, new): wraps in `ui/Section.jsx`'s existing shell (`bg-white rounded-xl p-5 shadow-sm border`) — identical padding/border/radius to every other Today section, no new values. It is appended as the **last** Section in Today's existing vertical `space-y-*` stack (exact placement — before/after the existing attention Sections — is Claude's Discretion per `06-CONTEXT.md`; either position uses the stack's existing gap value, no new spacing decision either way).
- **Desktop footer Settings button** (`Sidebar.jsx`): inserted into the existing `<div className="px-3 py-4 border-t border-ink-800 space-y-2">` footer group, using the exact same button classes as its siblings (`w-full flex items-center justify-center gap-1.5 px-3 py-2 rounded-lg text-xs font-medium ... transition-colors`) — no new padding/gap values, per `06-RESEARCH.md` Pattern 2's exact code example.
- **Mobile floating Settings button** (`Sidebar.jsx`): a 4th floating action button at `bottom-56` (14px × 4 = 224px, a confirmed default Tailwind spacing-scale key), continuing the existing `-16` step pattern (`bottom-52` → `bottom-36` → `bottom-20` → **`bottom-56`** sits above, not between, the existing three since it's the least time-critical action) — same `w-12 h-12 rounded-full` sizing as its siblings, no new size value.
- **Removed:** the `'overview'`/`'settings'` `NAV_ITEMS` entries' row spacing in the desktop `<nav>` and mobile bottom `<nav>` collapses automatically as the array shrinks — no manual gap recalculation needed, `space-y-1`/`justify-around` already handle variable item counts.

**Exceptions:** none beyond the pre-existing `01-UI-SPEC.md` exceptions (non-4px-multiple chrome padding inside `ui/` primitives, deferred to Phase 7) — this phase does not touch those primitives.

## Typography

No new sizes or weights — unchanged from `01-UI-SPEC.md`'s locked 2-size/2-weight (14px/400, 12px/600, plus the Mono 12px/400 data role) contract. Restated for reference:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 | 1.5 |
| Label | 12px (`text-xs`) | 600 | 1.4 |
| Mono (dense data) | 12px (`text-xs`), tabular-nums + tracking-wide | 400 | 1.4 |

**This phase's typography decisions:**

- Merged charts Section title (`"Activity"`) uses `Section`'s own built-in heading class (`text-sm font-semibold`, 14px/600) — identical to every other Today Section title (`Overdue Follow-Ups (N)`, `Stale Applications (N)`, etc.). No new size/weight introduced.
- New Settings footer button label (`"Settings"`) uses the exact same `text-xs font-medium` (12px/500) as its sibling footer buttons (Quick Capture, + Schedule, + Event, Refresh) — this is the same pre-existing `font-medium` (500) footer-button convention flagged as inherited debt in `05-UI-SPEC.md`, not a new violation introduced here. Do not "fix" it to 600 in isolation; it would make the new Settings button visually inconsistent with its four siblings in the same group. Candidate for Phase 7's full sweep.

## Copywriting Contract

This phase ships one new Section and one new button; every other string in scope is inherited unchanged from `OverviewTab.jsx` (charts) or `Sidebar.jsx`'s existing `NAV_ITEMS` (nav labels, now trimmed to 5).

| Element | Copy |
|---------|------|
| Merged charts Section title | `"Activity"` — icon: `Activity` (lucide-react, new import, size 16, strokeWidth 2 — matches every other Section icon's size/weight), `accent="ink"`, no count suffix (unlike list-based sections, this is data visualization, not an item queue) |
| Merged charts Section internals | No new copy — `"Application Funnel"`, `"Network by Status"`, `"Networking Activity"` sub-headings and their empty-state lines (`"No contacts yet."`, `'No logged interactions yet — use "+ Log Interaction" in Network.'`) carry over verbatim from `OverviewTab.jsx` |
| New Settings footer button label | `"Settings"` — icon: `NAV_ICON.settings` (lucide-react `Settings` gear, already defined, zero new import), size 13 to match its Quick Capture/+ Schedule/+ Event siblings |
| Primary CTA | No new CTA copy this phase. Nav item labels (`Today`, `Network`, `Grow`, `Pipeline`, `Calendar`) are unchanged strings, just a shorter array. |
| Empty state heading/body | No new empty-state copy this phase. `TodayTab.jsx`'s existing `EmptyState msg="✓ Nothing needs your attention. You're on top of it."` is **unchanged and explicitly does NOT gate the new charts Section** — see the Interaction Contract note below. This is a load-bearing decision for the checker/planner, not incidental: a fully caught-up user must still see their funnel/network/activity charts, matching `OverviewTab.jsx`'s prior behavior (gated only on data presence, never on "nothing needs attention"). |
| Error state | No new error copy this phase — no new error-producing logic is introduced by a pure nav-array/render-branch restructure. |
| Destructive confirmation | Unchanged — no destructive action is added, moved, or renamed this phase. |

**Interaction contract — charts Section placement relative to the `allEmpty` gate (resolves 06-RESEARCH.md Open Question 2):** `TodayTab.jsx`'s existing `if (allEmpty) return <EmptyState .../>` early-return must be scoped to short-circuit **only** the attention-item Sections above it, not the merged charts Section. Concretely: the charts Section's JSX and its underlying `funnelData`/`donutData`/`trendData` computation must render unconditionally (gated only on `hasRecruitingActivity`/`hasInteractions`/`contacts.length`, exactly as `OverviewTab.jsx` gated them), whether reached via the `allEmpty` early return or the normal render path. Do not extend `allEmpty`'s definition to include "no chartable data" — that conflates two independent concepts (nothing needs action vs. nothing to visualize) and was never part of `allEmpty`'s original meaning.

**Demo-mode copy note (D-04):** `DemoApp`'s Today render shows the same merged charts Section as authenticated Today — no demo-specific copy variant, since the charts have no AI/BYOK dependency and demo data (`demoData.js`) already shapes `contacts`/`apps`/`interactions` identically to the real data layer.
