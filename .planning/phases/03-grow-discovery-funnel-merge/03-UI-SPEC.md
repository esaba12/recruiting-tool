# Phase 3 — UI Design Contract

> Visual and interaction contract for the Grow (Companies → Coverage → People) discovery-funnel merge. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Aesthetic direction:** Industrial / control-panel — unchanged, inherited verbatim from Phase 1 (locked by PROJECT.md). This phase makes **zero new token-value decisions**; it is an information-architecture merge (GROW-01/GROW-02), not a visual-reskin phase (VIS-01 is Phase 7's job). Every color, font, weight, and spacing value below is a direct carry-forward of `01-UI-SPEC.md`'s already-validated contract, applied to the merged Grow surface. The only genuinely new visual/interaction decisions this phase makes are structural: how 3 previously-separate destinations (Explore, Coverage, Discover) present as one page, and how they visually connect (D-01 through D-05 in `03-CONTEXT.md`).

**Autonomous-run note:** this UI-SPEC was produced in a zero-check-in run. Every place below marked **[ASSUMPTION]** is a discretionary call made from `03-CONTEXT.md`'s "Claude's Discretion" list, Phase 1's locked system, and this project's established component precedent (`TodayTab.jsx`'s Section pattern, `NETWORK_VIEWS`' existing icon choices) — flag these for a quick human skim before/during planning rather than treating them as re-litigated decisions.

## Page Structure (D-01 / D-02 / D-03)

Grow is a **single scrollable page**, three sections, always in this order, always rendered — no tab/segmented-control switching, no accordion:

| Order | Section | Wraps existing component | Icon (lucide-react) | Accent tier |
|-------|---------|---------------------------|----------------------|-------------|
| 1 | **Companies** | `ExploreTab.jsx` (minus its own outer wrapper spacing) | `Building2` | `ink` (neutral) |
| 2 | **Coverage** | `ReferralCoverageTab.jsx` | `Target` — **[ASSUMPTION]** reused verbatim from `NETWORK_VIEWS`' existing `coverage` entry icon, so the icon a user already associates with this concept in the old segmented control carries over unchanged | `ink` (neutral) |
| 3 | **People** | `DiscoverTab.jsx` | `UserSearch` — **[ASSUMPTION]** reused verbatim from `NETWORK_VIEWS`' existing `discover` entry icon, same continuity rationale | `ink` (neutral) |

**No page-level "Grow" H1.** **[ASSUMPTION]**, based on established precedent: no other tab in this app (`OverviewTab`, `PipelineTab`, `TodayTab`) renders a redundant page-title heading above its content — the Sidebar nav item already carries that identity. Adding one here would be a new pattern, not a carried-forward one. Page identity comes entirely from the 3 section headers below.

**Section chrome — reuse `TodayTab.jsx`'s `Section` component shape exactly, with `accent="ink"` for all three** (its existing neutral tier: `border-ink-200` / `text-ink-700` heading / `bg-white rounded-xl p-5 shadow-sm border`). **[ASSUMPTION, rationale]:** `Section`'s existing tier system (`danger`/`warning`/`ink`/`accent`) encodes *urgency*, which doesn't apply here — Companies/Coverage/People are process stages, not priority tiers, and the danger/warning/success colors are already spoken for *inside* each section (Coverage/People's own gap/weak/strong row-level badges). Giving all three sections the same neutral `ink` frame keeps that inner row-level color-coding legible and unambiguous, and avoids a 4th, conflicting color-coding layer at the section-chrome level.

**New this phase — a small Mono step index in each section header**, satisfying D-03's "visually teaches the funnel order on first visit" goal with a concrete, minimal addition (not a new component family):
```
[01] [Building2 icon] Companies                    <-- header row
[02] [Target icon]    Coverage
[03] [UserSearch icon] People
```
- Step index renders via the existing `Mono` primitive (`ui/Mono.jsx`, 12px/400/`tabular-nums`/`tracking-wide`), color `text-ink-500` (not `ink-400` — matches Phase 1's own WCAG-fix precedent for small decorative-adjacent ink text against a light surface).
- Order: `[Mono step]  [Icon]  [Title]`, all inline, `gap-1.5`, matching `Section`'s existing icon+title flex row.
- This is the **only new visual element** this phase introduces beyond restructuring existing markup.

**Section internal cap (D-02):** each section's *primary* list is capped to **top 5** with a `+N more — Show all` / `Show fewer` expander, reusing `TodayTab.jsx`'s exact `RowCap` component and copy verbatim (cap=5, same toggle text, same tier-colored link styling). Applies to:
- Companies: the ranked company-card list (`shown` in `ExploreTab.jsx`).
- Coverage: the target-company row list (`rows` in `ReferralCoverageTab.jsx`).
- People: the "✨ Recommended" candidate list (top-level `recommended` array in `DiscoverTab.jsx`).

**Out of cap scope [ASSUMPTION]:** People's "By company" sub-view nested candidate lists (candidates *within* one company row) are **not** additionally capped this phase — D-02's scannability goal is about the page's top-level shape, and adding a second nested cap layer inside an already-secondary view is scope creep beyond what D-02 asked for. Leave that nested list's existing uncapped rendering as-is.

**Empty states, all 3 sections always visible (D-03):**

| Section | State | Behavior |
|---------|-------|----------|
| Companies | No prefs saved yet | Renders `CompanyOnboarding.jsx` inline as the section's body — unchanged, existing gate. |
| Companies | Prefs saved, zero results | Existing `EmptyState` copy, unchanged: *"No companies yet — hit ↻ Refresh, or edit your interests."* |
| Coverage | Zero target companies | **New EmptyState**, pointing up: *"Add target companies above to see referral gaps."* — see Interaction Contract below for how the section still exposes its own manual-entry path underneath this message. |
| Coverage | ≥1 target, mixed statuses | Unchanged existing row rendering (gap/weak/strong sort, badges). |
| People | Zero target companies | **New EmptyState** (replaces stale cross-tab copy — see Copywriting Contract): *"Add target companies above to see people to reach out to — People uses the same list."* |
| People | ≥1 target, zero recommendations yet | Unchanged existing copy: *"No recommendations yet — hit "Refresh now" to search your gap companies."* |

**Coverage's manual target-list textarea — preserved, not promoted [ASSUMPTION].** `ReferralCoverageTab.jsx` today auto-expands its own freeform "🎯 Target companies" textarea editor whenever the list is empty. That auto-expand behavior now conflicts with D-03's "EmptyState pointing up to Companies" contract (two competing calls-to-action at once). Resolution: the textarea/editor **capability is fully preserved** (GROW-02) but **no longer auto-expands** when empty — it stays behind its existing "▼ edit" toggle, with the new EmptyState message rendered above it as the primary steer toward Companies. A user who wants to paste a freeform list (not sourced from Companies' ranked results) still can, one click away, exactly as before — this is not a feature removal, only a default-visibility change consistent with D-03's stated section-always-points-up intent.

## Interaction Contract — Cross-Section Linking (D-04 / D-05)

This is the single decision that makes 3 stacked sections read as one connected flow, not three unrelated lists — treat it as load-bearing, not cosmetic.

**Mechanic (unchanged shape, new consumer):** the existing `{ company, ts: Date.now() }` focus-object pattern (already used by Coverage→Discover today) is reused verbatim. The `ts` timestamp is required, not optional — it's what makes a repeat click on the same company re-trigger the scroll+highlight even though the string itself didn't change (NAV-03's repeat-click requirement, and this phase's own success criterion 1 depend on this).

| Trigger | Source | Target section | Behavior |
|---------|--------|-----------------|----------|
| `+ Add to targets` click | Companies (`CompanyCard`) | Coverage | Smooth-scroll the **Coverage section** into view (`scrollIntoView({ behavior: 'smooth', block: 'start' })` on the section wrapper), then apply a `ring-2 ring-accent-300` highlight to **that specific company's row** inside Coverage. |
| `🔍 Find people` click | Coverage (per-company row) | People | Smooth-scroll the **People section** into view, switch People's internal view to "By company" if not already there, run/reuse its existing per-company search, then apply the same `ring-2 ring-accent-300` highlight to that company's row — this is `DiscoverTab.jsx`'s existing `focus` effect, unchanged, just re-triggered from a same-page scroll instead of a tab switch. |
| External deep-link (Pipeline's "who could I meet here" → `goFindPeople`) | `App.jsx` | Grow, People section | Lands on **Grow** (not Network) with the People section scrolled-to and the matching company row highlighted — same D-04 mechanic, not a second bespoke path (D-05). |

**Highlight visual spec:**
- Ring: `ring-2 ring-accent-300` — the exact class already in production use in `DiscoverTab.jsx`'s `byCompany` row (zero new CSS).
- Persistence: **matches existing behavior — no auto-fade timer.** The ring stays as long as the row's key matches the live `focus.company` (i.e., until the next click elsewhere fires a new focus event). **[ASSUMPTION]:** introducing a new auto-fade timeout would be a behavior change beyond what D-04 asked for ("briefly highlight") — reusing the exact non-fading precedent already shipped in `DiscoverTab.jsx` is the lower-risk, byte-consistent choice. If a human reviewer wants an actual timed fade, that's a one-line follow-up (`setTimeout` clearing local highlight state), not a blocker for this phase.
- Scroll timing: match `DiscoverTab.jsx`'s existing pattern — `setTimeout(() => el.scrollIntoView(...), 100)` after the row ref is guaranteed mounted (same 100ms buffer already in production).

**Do not** silently update data in place or expand an inline sub-panel instead of scrolling — D-04 explicitly rejected both alternatives as not reading as "connected."

## Spacing Scale

Declared values (unchanged from Phase 1 — must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**This phase's specific application:** the gap between Grow's 3 stacked sections is `space-y-4` (16px / `md`) — a direct, deliberate match to `TodayTab.jsx`'s existing outer wrapper (`<div className="space-y-4">`), not a fresh 24px "Section padding" pick from the abstract scale. **[ASSUMPTION, rationale]:** D-01 explicitly says this page "mirrors TodayTab's proven Section pattern" — matching its actual shipped spacing value byte-for-byte is more consistent with that instruction than re-deriving a technically-more-semantically-correct value from the general scale table. Section internal padding stays `p-5` (20px), the same carried-forward Phase 1 micro-exception already documented and accepted in `01-UI-SPEC.md` (not re-litigated here).

**Exceptions:** none new. The non-4px-multiple chrome-padding exceptions Phase 1 already documented (`px-2.5`, `py-1.5` in shared `ui/` primitives) carry forward unchanged and are still out of scope for a sweep (Phase 7's job).

## Typography

Unchanged from Phase 1 — no new sizes, no new weights, this phase does not touch the typography contract:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (Public Sans) | 1.5 |
| Label | 12px (`text-xs`) | 600 (semibold) | 1.4 |
| Data / Mono | 12px (`text-xs`, `tabular-nums` + `tracking-wide`) | 400 (IBM Plex Mono) | 1.4 |
| Heading (section titles, frozen scope per Phase 1) | existing per-component (`text-sm` for `Section` titles, `text-lg` for `CompanyOnboarding`-adjacent headings) | 600 | 1.2 |

**New this phase — one specific Mono application:** the section-header step index (`01`/`02`/`03`) described in Page Structure above uses the `Mono` primitive exactly as Phase 1 specified it (`font-mono text-xs font-normal tabular-nums tracking-wide`), color `text-ink-500`.

**Recommended, not required [ASSUMPTION — discretionary polish, not a checker-blocking gate]:** since this phase already touches render code in all three merged components, wrapping their existing dense/numeric display strings in `<Mono>` (fit-score numbers like `"fit 8/10"`, "Updated Xh ago" timestamps, candidate `score` values) would extend VIS-02's rollout at near-zero marginal cost. This is **not** a Phase 3 requirement (VIS-02 is scoped to Phase 1 in `ROADMAP.md`'s traceability table, and Phase 3's requirements are GROW-01/GROW-02 only) — flag it as an easy pickup for whoever plans this phase, but do not fail the UI check over it.

## Color

Unchanged from Phase 1 — no new hex values, no new token families. This phase's only color decision is *which existing tokens apply to which merged-page elements*:

| Role | Value | Usage in Grow |
|------|-------|----------------|
| Dominant (60%) | `canvas` `#f2f3f4` | Page background (unchanged, inherited from `AppShell`) |
| Secondary (30%) | `ink` scale | Section chrome (`bg-white` cards on `border-ink-200`), all 3 section headers/subtitles, step-index Mono text (`ink-500`) |
| Accent (10%) | `accent-500/600/700` | Every primary CTA across the 3 sections (`+ Add to targets`, `🔍 Find people`, `+ Add to Contacts`, `↻ Refresh`/`↻ Refresh now` active states), the cross-section highlight ring (`accent-300`), focus rings |
| Destructive | `danger` scale | Inline error banners (Exa/Claude call failures — unchanged existing pattern), Coverage's "No contact" gap badge (`danger-100`/`danger-700`, unchanged) |

Accent reserved for: primary buttons (Add/Find people/Add to Contacts/Refresh-active), the D-04 highlight ring, links, focus rings — **not** for the section chrome itself (sections stay neutral `ink`, per Page Structure above).

**Known pre-existing off-token usage — out of scope, carried forward unchanged.** Two spots inside the merged components use raw Tailwind `indigo-*` classes that were never part of Phase 1's 5-family token system (`ink`/`accent`/`success`/`warning`/`danger`):
- `ExploreTab.jsx`'s `CompanyCard` domain badge: `bg-indigo-50 text-indigo-600`.
- `ReferralCoverageTab.jsx`'s referral-chain path label: `text-indigo-600`.

These predate this phase and Phase 1 explicitly deferred this exact class of cleanup (`PipelineTab.jsx`'s `orange-*`, `JobDetailModal.jsx`'s `indigo-*` — see `01-UI-SPEC.md` "Open Questions Resolved") to Phase 7's full sweep. Consistent with that precedent: **do not fix these as a drive-by in Phase 3** — note them here so they aren't mistaken for a regression this phase introduced, and so Phase 7's sweep has two more confirmed instances on its list.
