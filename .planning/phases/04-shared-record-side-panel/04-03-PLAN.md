## Resolved implementation decision — where the D-05 record stack lives

04-RESEARCH.md Open Question 1 asked whether the in-place-swap stack belongs (a) at each call site or (b) in a shared `useRecordPanel()` hook, and recommended (b) to avoid duplicating stack logic across six call sites.

**Chosen: neither — the swap stays inside `ApplicationPanelBody`, as a single `useState`, duplicated at zero call sites.**

Rationale, verified against the current source rather than assumed:
- Record-to-record navigation exists in exactly one place in the app today: the application modal's dossier panel opening a contact. `ContactPanelBody` opens only non-record surfaces (the interaction-logging dialog and the inline draft panel), which D-05 leaves as-is. `JobPanelBody` opens nothing. So the maximum stack depth is 2, and it has exactly one entry point.
- A shared hook would require rewriting `selectedContactId` / `selectedAppId` / `editing` / `addingFor` / `addingNew` state management at all six call-site files and re-deriving per-body prop sets there — a much larger diff against the zero-regression bar of PANEL-02, to serve one two-deep stack.
- Keeping it in the body means 04-RESEARCH.md Pitfall 3 (nested prop threading) is satisfied structurally: the swapped-in contact is handed `contacts`, `interactions`, `relationships`, and `onRefreshRelationships` from the application body's own props, exactly as the legacy nested render does today. There is no opportunity for a host component to hand it a different or empty slice.
- It is also strictly less code than today: the legacy version renders a whole second overlay; the new version renders one component instead of itself.
- D-03 is respected: the shell still has zero record-type knowledge. Dispatch lives in a body, one level below the shell, which is where 04-RESEARCH.md Pattern 3 says it may live.

If a future phase adds a second record-to-record entry point (for example a contact linking to an application), extracting a shared hook becomes worth it. It is not worth it for one edge.
