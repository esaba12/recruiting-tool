# Phase 5 — UI Design Contract

> Visual and interaction contract for the Pipeline + Job Boards merge. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Aesthetic direction:** Industrial / control-panel (unchanged, locked by PROJECT.md and Phase 1's `01-UI-SPEC.md`). This phase introduces **zero new visual-hierarchy decisions** — it is a pure component-tree reshuffle (D-02: "rename + wrap, not a rewrite"). The only genuinely new UI surface is the segmented-control switcher itself; every other pixel in scope (Applications list, Job Boards board/card/calendar UI) is an unmodified body carried over verbatim from the pre-merge `PipelineTab.jsx`/`jobBoards/GitHubTab.jsx`. This UI-SPEC should be read against that narrow scope, the same way `01-UI-SPEC.md` was read against its token-only scope.

**Hard constraint honored:** `ApplicationsView.jsx` and `JobBoardsView.jsx` (the renamed bodies) get **zero visual changes** beyond what a straight file rename implies (per D-02/RESEARCH.md Anti-Patterns). Nothing in this contract authorizes restyling either body — it governs only the new shell chrome (`PipelineTab.jsx`'s segmented control) and confirms nothing else changes.

## Spacing Scale

Declared values (must be multiples of 4) — unchanged from `01-UI-SPEC.md`, restated for reference:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**This phase's specific spacing decisions:**

- The new `PipelineTab.jsx` shell wraps its segmented control in the exact same chrome row pattern `NetworkTab` uses today (`className="flex border border-ink-200 rounded-full overflow-hidden text-xs font-medium"`, segment buttons `px-3 py-1` internal, `gap-1.5` between icon and label) — do not invent new padding/gap values for the switcher; copy `NETWORK_VIEWS`'s exact classes verbatim (per RESEARCH.md's "Don't Hand-Roll" table).
- The switcher sits in its own row above whichever body is mounted, with the existing app-wide `mb-4` bottom margin used by every comparable toolbar row (`NetworkTab`'s filter/search/view-switch row uses this) — apply the same `mb-4` between the switcher row and the active view's own content.
- Per RESEARCH.md Open Question 2: neither `ApplicationsView.jsx` nor `JobBoardsView.jsx` currently renders its own page-level `<h1>`/header before its first content block (`DuplicatesPanel`/`TrackedBoardsPanel` respectively) — so no header-strip is required the way Phase 3's `GrowTab` had to strip `ExploreTab`'s header. **Executor must still visually verify** (render + screenshot, per the global `frontend_aesthetics` directive) that the switcher row plus each body's own top element reads with correct spacing before considering the phase visually done — this is a verify-not-assume step, not a spacing value this contract can pre-declare with certainty.

**Exceptions:** none beyond the pre-existing `01-UI-SPEC.md` exceptions (non-4px-multiple chrome padding inside `ui/` primitives, deferred to Phase 7) — this phase does not touch those primitives.

## Typography

No new sizes or weights — unchanged from `01-UI-SPEC.md`'s locked 2-size/2-weight (14px/400, 12px/600, plus the Mono 12px/400 data role) contract. Restated for reference:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 | 1.5 |
| Label | 12px (`text-xs`) | 600 | 1.4 |
| Mono (dense data) | 12px (`text-xs`), tabular-nums + tracking-wide | 400 | 1.4 |

**Known, inherited exception — not introduced by this phase:** the segmented-control pattern this phase copies verbatim from `NetworkTab`'s `NETWORK_VIEWS` (and mirrored by `RepoJobsView.jsx`'s own internal list/calendar toggle) uses a wrapper `text-xs font-medium` (weight 500) className that predates Phase 1 and was never in Phase 1's 10-file scope (`App.jsx`'s inline `NetworkTab` was explicitly out of that phase's file boundary). D-01 requires this phase's new switcher to match that existing convention exactly, which means the new Pipeline segmented control will also carry this same `font-medium` (500) — a third weight technically outside the 2-weight ceiling, but a **copy of pre-existing debt, not a new violation**. Do not "fix" this by changing the switcher's weight to 600 in isolation — that would make the new Pipeline switcher visually inconsistent with the Network/Job-Boards-internal switchers it's supposed to match (D-01's explicit requirement), trading one inconsistency for a worse one. This is a candidate for Phase 7's full sweep (which already owns reconciling `App.jsx`'s inline styles with the Phase 1 primitive contract), not this phase.

## Color

No new tokens or hues — this phase uses only the already-validated `ink`/`accent` ramps from `01-UI-SPEC.md`. Restated for reference:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `canvas` `#f2f3f4` | Page background (unchanged) |
| Secondary (30%) | `ink` scale | Switcher border (`ink-200`), inactive segment text (`ink-500`), inactive hover (`ink-50`), active segment fill (`ink-900` solid, white text) |
| Accent (10%) | `accent-500`/`600`/`700` | Reserved for: primary Button, active Tabs state, ChipToggleGroup selected state, focus rings, links, Champion badge — **the new Pipeline segmented control does NOT use accent for its active state**, matching `NETWORK_VIEWS`'s existing precedent of using `ink-900` (not `accent`) for view-switcher active state. View switching is a neutral navigational action, not a primary/CTA action — accent stays reserved for the elements already listed, this phase adds nothing to that list. |
| Destructive | `danger` scale | Destructive actions only (unchanged) — this phase introduces no new destructive action |

**Accent reserved for (explicit list, unchanged by this phase):** primary Button fill, active Tabs indicator, ChipToggleGroup selected chip, focus rings, inline links, Champion status badge. The Pipeline/Job-Boards segmented control's active state is `ink-900`, matching `NETWORK_VIEWS` and `RepoJobsView`'s internal toggle — confirmed by direct code read, not assumed.

## Copywriting Contract

This phase ships exactly one new user-facing UI element (the segmented control) — every other string in scope is inherited unchanged from the renamed bodies.

| Element | Copy |
|---------|------|
| Segment 1 label | "Applications" — icon: `Kanban` (lucide-react, already imported as `NAV_ICON.pipeline`, size 13, strokeWidth 2.25) |
| Segment 2 label | "Job Boards" — icon: `GitFork` (lucide-react, reused from the removed `NAV_ICON.github` entry per D-05's explicit reuse note — zero new import, 15+ months of established "Job Boards" meaning in this app) |
| Primary CTA | No new CTA copy this phase. `ApplicationsView.jsx` keeps its existing "+ Add Application" button verbatim; `JobBoardsView.jsx` keeps its existing "+ Add" / "✚ Pull all tracked boards" copy verbatim (D-02: zero logic/copy changes to either body). |
| Empty state heading | No new empty-state copy this phase — both bodies' existing `EmptyState` usages carry over unchanged. |
| Empty state body | Same as above — no copy edits in scope. |
| Error state | No new error copy this phase — no new error-producing logic is introduced by a shell/rename change. |
| Destructive confirmation | Unchanged — `DuplicatesPanel`'s existing "Archive N duplicates" native-`confirm()` pattern inside `ApplicationsView.jsx` carries over verbatim; this phase adds no new destructive action. |

**Demo-mode copy note (D-03):** when `views` is filtered down to a single entry (`DEMO_PIPELINE_VIEWS`, Applications only), **the switcher chrome must not render at all** — not a disabled/single-option toggle, not a locked-with-tooltip state. This mirrors D-03's "hidden entirely" decision and avoids a pointless single-button "switcher" floating in the demo UI. Concretely: `PipelineTab.jsx` should render the segmented-control `<div>` only when `views.length > 1`. (`NetworkTab`'s own demo path never hits this edge case since `DEMO_NETWORK_VIEWS` still has 3 entries — this is a genuinely new condition Pipeline's shell must add that `NetworkTab` didn't need, flagged here since it's an actual UI decision, not copy inherited from precedent.)
