# Phase 2 — UI Design Contract

> Visual and interaction contract for the "Today" unified attention feed. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** this phase is an information-architecture/composition change, not a token phase. Phase 1's `01-UI-SPEC.md` already locked all color, typography, and spacing token *values* app-wide — this document does not redeclare or alter them. It specifies how Phase 1's tokens and primitives (`Card`, `Badge`, `Mono`, the 5 locked color families) compose into 9 attention sections built from 5 distinct row/card shapes, plus the new "Today" nav entry. Every hex/px value cited below is copied verbatim from `01-UI-SPEC.md` for reference only — the source of truth for token values remains that file.

## Typography

Inherited verbatim from `01-UI-SPEC.md` — this phase declares zero new sizes and zero new weights. Reference:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label (Badge, section headers, row primary text) | 12px (labels) / 14px (row primary text — e.g. contact name, company name, matches existing `ActionsTab`/`KeepInTouchTab` row conventions) | 600 | 1.4 |
| Data / Mono | 12px, `tabular-nums` + `tracking-wide` | 400 | 1.4 |

**Section header treatment (new composition, built from existing typography roles only):**

```
[Icon 16px]  Section Title (14px/600, tier-colored)  (N)         ← count in same weight/color as title, NOT Mono
             Optional subtitle (12px/400, text-ink-400)
```

The `(N)` count stays in the header's own Label typography (600 weight), not wrapped in `<Mono>` — Phase 1 explicitly excludes "large single-hero-number displays" and heading-adjacent numerals from Mono's dense-data role (01-UI-SPEC.md, Typography section); a section-header item count is a heading annotation, not a table/panel data field, and wrapping only the digits in a competing 400-weight font next to a 600-weight title would visually clash rather than aid scanning.

### Mono usage per item type (VIS-02 application to Today's 5 new row shapes)

Every date, day-count, and deadline-countdown token in Today's rows wraps in `<Mono>`, following the exact established call-site pattern already shipped in `ContactsTable.jsx`, `PipelineTab.jsx`, and `jobBoards/JobCard.jsx` (Phase 1, plans 01-03/01-04): **wrap only the date/number token itself, not the surrounding sentence** — connecting words ("Was due", "d ago", "in stage") stay in the row's existing 12px/400 `text-ink-500` (or tier color) prose, exactly as `<Mono>{days}</Mono>d in {stage}` and `<Mono>{fmt(a.closedDate)}</Mono>` already do in `PipelineTab.jsx`. Do not wrap the whole meta line as a single `<Mono>` block — that was considered and rejected because it would also mono-ize connector words that aren't dense data, breaking the established pattern's exact scope.

| Item type | Field | Before | After |
|-----------|-------|--------|-------|
| Contact Row | Overdue meta | `Was due {fmt(date)} ({N}d ago)` | `Was due <Mono>{fmt(date)}</Mono> (<Mono className={overdue-color}>{N}d</Mono> ago)` |
| Contact Row | Schedule-by meta | `Wanted by {fmt(date)} ({N}d ago)` / `Schedule by {fmt(date)}` | Same pattern — date and day-count each individually wrapped |
| Keep-in-Touch Card | Overdue status | `{N}d overdue` / `Due today` / `Never contacted` | `<Mono>{N}d</Mono> overdue`; `Due today` and `Never contacted` stay plain text (no numeral to Mono-ize) |
| Keep-in-Touch Card | Cadence | `every {N}d` | `every <Mono>{N}</Mono>d` |
| Keep-in-Touch Card | Last point of contact date | `{fmt(last.date)}` | `<Mono>{fmt(last.date)}</Mono>` |
| Application Row | Stale meta | `{N}d in {stage}` | `<Mono>{days}</Mono>d in {stage}` (verbatim match to `PipelineTab.jsx:186`) |
| Application Row | Applied/closed date (if shown) | `Applied {fmt(date)}` | `Applied <Mono>{fmt(date)}</Mono>` (verbatim match to `PipelineTab.jsx:178`) |
| OA Row | Due countdown | `Due {fmt(date)} ({N}d)` / `Was due {fmt(date)} ({N}d ago)` | Date and day-count each individually wrapped, same convention |
| OA Row | Needs-check state | `No stated deadline found — check manually` | No Mono — no numeral/date present |
| Timeline Find Card | Last-scan timestamp (section subtitle, not per-row) | `Last scan {timeAgo(...)}` | `Last scan <Mono>{timeAgo(...)}</Mono>` |
| Timeline Find Card | Date/time editable fields | `<input type="date">` / `<input type="time">` | **No Mono** — these are editable form controls (`Input`-family typography), not read-only dense-data display; Mono is reserved for display text per Phase 1's contract, never applied inside form inputs |

**Overdue-emphasis color-on-Mono pattern:** when a date/day-count is itself in an overdue/danger state, apply the tier color directly to the `<Mono>` element's `className` (e.g. `<Mono className="text-danger-600 font-medium">`), exactly matching `ContactsTable.jsx:97`'s established `overdue ? 'text-danger-600 font-medium' : ''` pattern — `tailwind-merge` (via `cn()`) already resolves the `font-medium` override against Mono's default `font-normal` correctly, so this is safe to reuse verbatim, not a new mechanism.

## Color

Inherited verbatim from `01-UI-SPEC.md` — no new hex values, no new token families. Reference (5 locked families only): `ink`, `accent`, `success`, `warning`, `danger`.

### Section accent-tier mapping (new composition decision this phase makes)

`ActionsTab.jsx`'s current `Section` component keys its `accent` prop to off-token literals (`red`/`orange`/`yellow`/`indigo`) that don't map onto Phase 1's locked 5-family set. This phase's `Section` component must be re-keyed to the 4 relevant locked families below — **not** a 6th/7th family, per Phase 1's explicit "Open Questions Resolved #1" hard constraint (same rule that already forced the `Champion`/`Technical`/`Onsite`/`LinkedIn`/`Meeting` badge remap).

Sections are grouped into **3 urgency tiers**, deliberately reusing the same hue across multiple sections within a tier (5 families cannot uniquely color 9 sections, and Phase 1 already established the precedent of grouping semantically-related states onto one shared family rather than inventing new hues). Sections are visually differentiated within a tier by icon + title + position, not by a unique border color per section — this is intentional, not a shortcut: it reinforces D-02's time-sensitivity ordering by making the color bands themselves read top-to-bottom as "most urgent → least urgent → distinct AI-suggestion type."

| Tier | Family | Sections (in D-02 order) | Border | Heading text |
|------|--------|---------------------------|--------|--------------|
| Blocking (top of feed) | `danger` | 1. Overdue Follow-Ups · 2. Stale Applications · 3. High Urgency Contacts | `border-danger-200` | `text-danger-700` |
| Due soon | `warning` | 4. Keep in Touch Due · 5. Job Boards Needs-Review · 7. OA-Due | `border-warning-200` | `text-warning-700` |
| Queued / housekeeping | `ink` | 6. Want to Schedule · 8. OA-Needs-Check | `border-ink-200` | `text-ink-700` |
| AI-proposed (bottom, distinct action type) | `accent` | 9. Timeline Finds | `border-accent-200` | `text-accent-700` |

**Note on D-02's literal order vs. this tier grouping:** D-02's canonical order (Overdue → Stale → High Urgency → Keep in Touch → Needs-Review → Want to Schedule → OA-Due → OA-Needs-Check → Timeline Finds) is followed exactly for render order — the tier table above is a color grouping laid over that fixed order, not a re-sort. OA-Due (position 7, `warning`) sits between two `ink`-tier sections (Want to Schedule at 6, OA-Needs-Check at 8) in the render order — this is expected and correct; do not reorder sections to cluster same-tier colors together, since D-02's time-sensitivity order is the locked decision and takes priority over color-clustering.

| 4. Keep in Touch Due | `HeartHandshake` | Verbatim reuse of `KeepInTouchTab.jsx`'s own existing header icon |

## Feed Composition Contract

### Page-level structure

`TodayTab.jsx` renders a single-column vertical stack of 9 `Section` cards (`space-y-4`/16px between them — see Spacing), in the exact D-02 order. A section renders `null` (not an empty `Card` shell) when its underlying array has zero items — matching `ActionsTab.jsx`'s existing per-section `.length > 0 &&` guard pattern exactly. If **all 9** arrays are empty, render one page-level `EmptyState` in place of the stack (see Copywriting Contract), matching `ActionsTab.jsx`'s existing all-empty behavior.

### Per-section row cap ("Show N more")

Reuse `CalendarTab.jsx`'s existing capped-list precedent (`FEED_LATER_CAP` pattern) rather than inventing a new one: each section shows its **first 5 rows** by default; if more exist, render a text control below the row list in the section's tier color (not `text-ink-400` as `CalendarTab.jsx`'s static hint uses — Today's version is *interactive*, so it uses the accent-reserved-for-interactive-affordances convention): `+{N} more — Show all`. Clicking toggles the section to show its full list; clicking again (now reading `Show fewer`) re-collapses to 5. This is a new interaction (CalendarTab's version is a static, non-interactive hint), justified because Today aggregates 9 sections at once (much higher total row-count risk than Calendar's single "later" bucket) — call this out explicitly to the executor as new behavior layered on an existing visual precedent, not a verbatim copy.

### Item-type row specifications (5 distinct shapes across the 9 sections)

**Type 1 — Contact Row** (plain list row, `divide-y divide-ink-100` inside the section `Card`, `py-2.5`)
Used by: Overdue Follow-Ups, High Urgency Contacts, Want to Schedule.
Layout: left block (name 14px/600 `text-ink-900`; secondary line `company · role` 12px/400 `text-ink-500`; optional `mailto:` link 12px `text-accent-500`) / right block (`text-right shrink-0`: status/urgency `Badge`, then a Mono-wrapped meta line per the Typography table above, then the section's existing inline action buttons — e.g. "Draft follow-up"/"Mark followed up", "Draft outreach"/"✓ Scheduled").
**New click-target contract (ATTN-02):** the left name/company block's `onClick` changes from today's "toggle inline expand" to **"open `ContactDetailModal`"** (full record — satisfies ATTN-02). The existing inline "Draft follow-up"/"Draft outreach" expand-to-`DraftPanel` affordance moves to its own small dedicated toggle (a `▾`/chevron icon-button placed inline next to the row's other action buttons, not layered on the name-click), so the two behaviors (open full record vs. expand inline draft panel) occupy visually separate, non-conflicting click zones. This is genuinely new wiring, not a relocation — the executor must not assume the existing `expanded` toggle can stay bound to the name block once that block is repurposed for the modal.

**Type 2 — Keep-in-Touch Card** (full `Card`-style row, own visual weight — distinct from Type 1's plain divide-y row, matching `KeepInTouchTab.jsx`'s existing treatment exactly)
Used by: Keep in Touch Due only.
Layout: unchanged from `KeepInTouchTab.jsx` — `bg-white rounded-xl px-4 py-3 shadow-sm border` (border color follows the tier-4 warning family instead of the current conditional `accent-200`/`ink-100`, to match this section's tier assignment above — the overdue-highlight-via-border behavior itself is preserved, just recolored: overdue rows use `border-warning-300`, non-overdue rows use `border-ink-100`), left block (name/company/role, status `Badge`, tie-strength label), last-point-of-contact line, right block (overdue-status text, `MetButton`, "Log" button).
Click target: **unchanged** — the entire left block's existing `onClick={() => onEdit(c)}` already opens `ContactDetailModal`; this is the one of the 5 types that already satisfied ATTN-02 before this phase (per RESEARCH.md).

**Type 3 — Application Row** (plain list row, same shape family as Type 1 but application-shaped fields)
Used by: Stale Applications, Job Boards Needs-Review.
Layout: left block (company 14px/600 `text-ink-900`; role 12px/400 `text-ink-500`; optional "View JD ↗" link) / right block (stage `Badge`, Mono-wrapped `{N}d in {stage}` meta).
**New click-target contract (ATTN-02, corrected D-04):** the row (at minimum the left company/role block) opens `ApplicationDetailModal`, wired with the exact same prop set `PipelineTab.jsx` already passes (`app`, `contacts`, `apps`, `interactions`, `relationships`, `onStatusChange`, `onClose`, `onDelete`, `onSaved`, `onFindPeople`, `onRefresh`, `onRefreshRelationships`). **`onFindPeople` must be `App.jsx`'s existing `goFindPeople` closure** — omitting it doesn't crash (fail-soft `onFindPeople &&` guard inside the modal) but silently removes the "Find people →" cross-tab relay, a real regression per the carried-forward STATE.md blocker.
**Job Boards Needs-Review variant only:** below the meta line, render an inline triage quick-action chip row reusing `JobCard.jsx`'s existing `BUCKET_TAG`-styled pill treatment, scoped to the 4 actionable buckets (`applying`/`maybe`/`applied`/`pass` — omit `all`/`review` since the row is already in the Needs-Review bucket by definition). Each chip's `onClick` must call `e.stopPropagation()` before invoking the existing triage-change logic (`changeStatus`/`updateApplication`), so tapping a chip doesn't also trigger the row's modal-open click — this satisfies D-05's "carry forward triage-bucket quick actions" without requiring the modal to open first.

**Type 4 — OA Row** (plain list row, same shape family as Type 1/3 but OA-shaped fields)
Used by: OA-Due, OA-Needs-Check.
Layout: unchanged from `ActionsTab.jsx`'s existing `OaRow` — left block (company/role, "Open assessment ↗" external link) / right block (Mono-wrapped due-countdown text or the plain "No stated deadline found — check manually" needs-check copy, "✓ Mark completed" button).
Click target: same `ApplicationDetailModal` wiring as Type 3 (RESEARCH.md's deep-link table groups OA-Due/OA-Needs-Check under the same "Application" record-type target as Stale Applications) — the external "Open assessment ↗" link and "✓ Mark completed" button stay as separate right-block click zones with their own `stopPropagation`, exactly mirroring Type 3's chip-vs-row-click separation pattern.

**Type 5 — Timeline Find Card** (editable review card, distinct interaction model — approve/dismiss, not view/edit)
Used by: Timeline Finds only.
Layout: unchanged internals from `TimelineFindsPanel.jsx`'s existing per-item card (`bg-white rounded-lg p-3 border border-ink-100`: source-type `Badge`, editable title `input`, editable date/time `input`s, description snippet, "+ Add to Calendar" / "Dismiss" buttons) — **but the section's own outer chrome is standardized** to match the other 8 sections' `Section`/`Card` header (icon + title + count, tier-4 `accent` border/heading — see Color) instead of `TimelineFindsPanel.jsx`'s current bespoke `bg-gradient-to-r from-accent-50 to-indigo-50` collapsible-accordion header. The existing "↻ Rescan" control and "Last scan {timeAgo}" text move into the section's subtitle row (12px/400 `text-ink-400`, Mono-wrapped timestamp per Typography above), replacing the header's own accordion open/close toggle — Today's section-level expand/collapse (if the row-cap control above applies) supersedes `TimelineFindsPanel`'s bespoke `open`/`setOpen` accordion state.
Click target: **approve/dismiss-only, no full-record deep-link** — per D-04b/RESEARCH.md's finding that a Timeline Find is a proposed calendar event, not a pointer to an existing contact/app/job record. This is a deliberate, documented scope-narrowing of ATTN-02 for this one category, not an oversight.

## Navigation

**New sidebar entry (`Sidebar.jsx`'s `NAV_ITEMS`):** `{ id: 'today', label: 'Today' }`, inserted as the **first** item (position 0, ahead of Overview), per D-03.

**Icon (`lib/icons.js`'s `NAV_ICON` map):** `Gauge` (lucide-react) — chosen specifically for the "industrial/control-panel" aesthetic direction Phase 1 locked (`01-UI-SPEC.md`'s explicit "instrument panel" framing), consistent with ROADMAP.md Phase 7's eventual "gauge-like mono readouts" language for this same destination's KPI tiles. Rendered at the same `size={16} strokeWidth={2}` (desktop sidebar) / `size={18} strokeWidth={2}` (mobile bottom bar) as every other nav icon — no new icon-sizing convention.

**Sidebar badge count:** `counts.today` (replacing the current `counts.actions`), computed via the new `lib/attention.js` module's category functions summed together (`App.jsx`'s `AppInner`) — same badge-pill treatment already used for every other nav count (`bg-white/20` when active, `bg-ink-700 text-ink-300` when inactive), no new styling.

**Mobile:** Today occupies the first slot in both the bottom tab bar and any floating quick-action equivalents, matching desktop ordering — no mobile-specific layout variant beyond what `Sidebar.jsx`'s existing responsive split already provides.

**`/demo` nav:** `'today'` replaces `'actions'` in `DEMO_NAV_ITEMS`, rendering the identical Today tab and row/section visuals specified above, with the Timeline Finds section (#9) omitted entirely in demo mode (not just its content — the whole `Section` card, so the feed doesn't show an 8th visible-but-broken section header) per RESEARCH.md's Pitfall 4 (an anonymous demo visitor cannot trigger the Timeline Finds AI scan without a 401). This is a visibility rule, not a new visual treatment — sections 1–8 render identically in demo and authenticated mode.

## Copywriting Contract

| Element | Copy |
|---------|------|
