# Design system + charts

> Moved out of CLAUDE.md on 2026-10-16 (v1.3 spec 07). Dated "shipped" notes are history; check the code before trusting a detail.

## Design System (shipped July 2026)

Tailwind converted from a CDN script to a real build (Tailwind v4 + `@tailwindcss/vite` plugin — no `tailwind.config.js` needed, theme lives in `app/src/index.css`'s `@theme` block). One dominant color (`ink`, a warm charcoal scale — sidebar bg/text) + one sharp accent (`accent`, warm amber/orange — every primary button/active-state/link/focus-ring) replace the old flat `blue-600`/`gray-50` look; `success`/`warning`/`danger` tokens replace stock Tailwind green/yellow/red for status badges. Fonts: **Space Grotesk** (headings, applied globally to h1/h2/h3 via CSS, no per-component class needed), **Public Sans** (body), **IBM Plex Mono** (not yet used anywhere specific — reserved for dense data if needed later). **Color schemes + dark mode (2026-10-11):** five per-user schemes (Safety Orange default, Maize & Blue, Cobalt, Patina, Signal Rose) × Light/Dark/System, picked in Settings → Appearance (`components/AppearanceSection.jsx`). Architecture in `index.css`'s header comment: raw `--p-*` palettes per `[data-scheme]`, a `--t-*` role mapping that **flips** the ink scale in `[data-mode="dark"]` (so `text-ink-900` = "strongest text" works in both modes with zero `dark:` classes), exposed via `@theme inline`. Semantic tokens: `bg-surface` (never `bg-white`), `text-on-accent` (text on an accent fill — navy on maize), `text-on-fill` (text on solid ink/status fills), `text-link` (accent-colored text). `.theme-fixed` marks islands that stay dark in both modes (sidebar, mobile nav, onboarding rail, 404, network graph). Recharts/canvas read live tokens via `charts/theme.js`'s `useChartTheme()`. Persistence: `user_settings.appearance` (account, applied in `AuthContext`) + unscoped `rec_appearance` localStorage, read pre-paint by `public/theme-init.js` (external file because CSP is `script-src 'self'`). Contrast audited across all 10 combos — everything ≥4.5:1 except maize's light-mode button hover (3.45:1).

Layout is a persistent dark sidebar (`components/layout/Sidebar.jsx`) + full-width content area (`components/layout/AppShell.jsx`), collapsing to a bottom tab bar on mobile. `lucide-react` replaced emoji-as-icon usage everywhere except inside Notion select-option data values themselves (`STATUS_COLOR` keys like `'🟢 Warm'` still carry the emoji since that's the literal string written to/read from Notion — icons are looked up separately via `lib/icons.js`'s `statusIconFor()`, not derived from stripping the emoji out of the data). `framer-motion` powers exactly 3 moments: modal open/close (`ui/Modal.jsx`), tab-switch fade (`AppShell.jsx`), and nothing else — deliberately not scattered across hover states. Since v1.3 spec 09, animated elements are `m.*` (from `motion/react`) under the `<LazyMotion>` in `main.jsx`, whose `domAnimation` features load as their own chunk. Use `m.div`, not `motion.div`, in anything Today renders, or the full motion bundle lands back in the entry chunk. `layout`/drag animations need `domMax`, so check the bundle before adding one.

`App.jsx` was decomposed from ~1836 lines (monolithic, every tab inline) down to ~250 lines (root state/routing only) — every tab is now its own file under `components/`.

## Affordances: only clickable things look clickable (2026-10-17)

Rule: anything that does something on click answers the mouse (pointer **and** a hover state), and nothing else does. Concretely:
- **Hover/pointer only on handlers.** No `hover:*` or `cursor-pointer` on an element without `onClick`/`href` (or a native control). Card-level hover is fine only when the whole card is the click target; otherwise put the hover on the part that is (Today's Keep in Touch card lost its whole-card shadow; its open button carries the hover).
- **Clickable rows get feedback.** Row regions that open a side panel use Today's `ROW_HIT` (`cursor-pointer rounded-sm -mx-1.5 px-1.5 hover:bg-ink-50`). A row whose target can be missing (an action item with no contact) drops both pointer and hover.
- **`text-link` means a link.** Accent-colored text is reserved for things you can click. Labels and metadata ("Referred by …", Coverage's "↩ Path", Explore's "Why you:", Discover's field labels, Inbox's unread count) use ink tones. Decorative accents that can't be mistaken for links (step numbers, bullets, big stat numbers) are fine.
- **Read-only numbers aren't boxed as cards.** Stat readouts (Today's Funnel / Next Deadline / Activity, Job Boards' repo stats) sit unboxed or share one panel with dividers, because a bordered tile per number reads as a clickable card.
- **Badges that imply an action are the action.** Pipeline → Applications' "Need network" is a button that jumps to Grow → People for that company (it stays a plain badge where `onFindPeople` isn't wired, e.g. `/demo`). Status badges stay plain.

How it was audited: a headless-Chromium pass over every `/demo` tab, sub-view and side panel flagged (a) pointer or `hover:` elements with no React click handler on themselves or a row-sized ancestor, (b) clickable non-native elements with no hover feedback, (c) bordered small boxes containing nothing interactive, and (d) link-colored or underlined text that isn't interactive. A static pass over every `.jsx` file covered the tabs `/demo` hid at the time (Grow, Settings, Outbox, Job Boards). Known false positives: segmented-control wrappers, Learn's company-prep chip wrapper (it contains real buttons), Recharts surfaces (hover = tooltip), Pipeline Sheet cells (spreadsheet selection), modal backdrops.

## Charts (shipped July 2026)

`recharts` replaced the hand-rolled `<div>` bar/tile charts. All color/mark choices went through this repo's `dataviz` skill (six-check palette validator + form/mark-spec guidance) rather than being eyeballed:
- **Overview → Application Funnel**: real bar chart (`charts/BarChart.jsx`) + new stage-to-stage conversion % annotation (e.g. "Applied → Phone Screen: 18%"). Uses a single flat accent hue, not a per-stage ramp — axis position already encodes stage order, and no 6-step slice of the `accent` scale cleared the ordinal validator's lightness/contrast checks against the light canvas at that count (see `charts/theme.js`'s comments for the actual validator runs).
- **Overview → Network by Status**: donut chart (`charts/DonutChart.jsx`) replacing the colored-tile grid, fed by `STATUS_CHART_COLORS` in `charts/theme.js`. Always paired with a visible count legend (not hover-only) — required relief for a contrast WARN the validator flagged on two of the five status colors against the canvas.
- **Overview → Networking Activity**: new "interactions over time" trend (`charts/TrendChart.jsx`), trailing-10-week bucket of `interactions` data — a signal that had **zero visualization anywhere before this**. Requires `interactions` passed into `OverviewTab` from `App.jsx`.
- **Job Boards → Top Locations**: real horizontal bar chart, direct swap for the old manual-width `<div>` bars.
- **Pipeline**: deliberately no new chart — a Triage-bucket donut would mostly restate the Overview funnel (Triage and Stage are correlated).
