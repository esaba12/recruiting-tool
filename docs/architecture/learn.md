## Learn — interview-prep tracking (shipped 2026-09-28)

Top-level **Learn** tab (`components/LearnTab.jsx`, `components/learning/*`, `lib/learning/*`). Practice happens off-app (LeetCode, CodeSignal, mocks); Learn is where it's logged, measured against targets, and turned into what to do next. No in-app code editor/runner by design — "editor" here means the **Customize** panel.

- **Tracks** (`learning_tracks`), one per recruiting type, seeded from `lib/learning/templates.js` (SWE: NeetCode-style DSA patterns mapped to LeetCode tagSlugs + System Design + SQL + HTTP/Networking; IB; PM; Quant; blank Custom). `config` jsonb holds the customize state: `widgets` (which dashboard panels, in what order), `goals`, `leetcodeUsername`. First open asks which tracks to start (pre-picked from `profiles.focus`).
- **Customize panel** (`components/learning/CustomizePanel.jsx`): Topics (motion `Reorder` drag, target level, self-rating, hide, weight, LeetCode tags, ✨ AI topic suggestions staged-then-committed), Stats (widget toggle + reorder — catalog in `WIDGET_TYPES`), Goals (`GOAL_METRICS` × week/by-date/total × optional category/difficulty), Track (name, LeetCode username, archive). Saves immediately.
- **Mastery engine** (`lib/learning/mastery.js`, pure, `test/learningMastery.test.js`): per-topic level 0–5 from logs (30-day half-life decay × difficulty × outcome/score), blended with self-rating, plus the LeetCode lifetime tag counts as undated baseline evidence; `verified` flag when evidence is thin (rendered hatched). `rankGaps` = (target − level) × weight × demand, where demand comes from the Pipeline (interview-stage apps / OA due ≤21d whose role matches the track). `lib/learning/derive.js`'s `deriveTrack` is the per-track view both Learn and Today use.
- **LeetCode import** (`lib/learning/leetcodeImport.js`): public GraphQL via `/leetcode` → folded into `api/gh-api.js` (`?upstream=leetcode`, **auth-gated + rate-limited**, still 12/12 functions). Client sends `{op:'profile'|'questions', username|slugs}`; `api/_lib/leetcode.js` owns the only GraphQL strings (allowlist test in `test/leetcodeImport.test.js`). Last 20 accepted submissions → `learning_logs` (idempotent on submission id via the `(user_id, source, external_ref)` unique constraint); per-tag lifetime counts → `user_settings.leetcode_snapshot`. **Sync cadence + storage (2026-10-10):** every `SYNC_INTERVAL_MS` (3h) per browser, on load and on tab re-focus (`syncDue`; the old per-day gate let >20 solves/day scroll out of LeetCode's window unseen). Every attempt is stored once and kept (one `learning_logs` row per attempt, one `learning_items` row per problem); `snapshot.syncedIds` (capped 200) remembers what's stored, so a sync with nothing new is one GraphQL read and **zero** Supabase writes or re-reads (`unchanged: true`; the stats compare is key-order-insensitive because jsonb reorders keys). The username field commits on blur, Enter, and panel close/unmount (`planUsernameCommit`, accepts a pasted profile URL) and syncs immediately via `useLearning.setLeetcodeUsername`. It used to save on blur only, so Escape/✕ silently dropped it and sync never ran; a "Connect LeetCode" header link deep-links to Customize → Track when an LC track has no username. Gotcha: profile tag counts say `heap`/`sweep-line`, problem tags say `heap-priority-queue`/`line-sweep` — templates list both. CodeSignal/HackerRank have no API: logged as `kind:'assessment'`, prompted by Today's OA row ("Done — log how it went →").
- **Struggle-aware sync (2026-10-05)**: the profile query also pulls `recentSubmissionList` (last 20 submissions of *any* status — public, verified live). `summarizeAttempts` counts Wrong Answer/TLE/Runtime Error submissions within 24h before each accept (compile errors ignored): 0 → solved/confidence 4, 1 → solved/confidence 3, ≥2 → `hinted`; wrong submissions with no accept → one `failed` log (`externalRef: fail:<id>`, skipped while <30 min old). `reviewUpdates` replays freshly inserted logs through FSRS, so LeetCode struggles enter the re-solve queue automatically and a clean re-solve on LeetCode credits a queued review. Accepts older than the any-status window have unknown struggle and stay plain `solved`.
- **Languages + full history (2026-10-05)**: the profile query also reads `languageProblemCount` (lifetime solves per language, which overlap across languages) and each submission's `lang`. `mergeLanguageStats` accumulates per-language solves / first-try / struggled / gave-up into `leetcode_snapshot.languageStats` across syncs, deduped by attempt id (capped `seen` list). `syncLeetcode({ prev })` carries accumulating snapshot fields over for the same username. `LanguagesWidget` ('languages', `lcOnly`) renders it. **Older solves:** Customize → Track → "Import full history" takes a pasted `LEETCODE_SESSION` cookie. `api/_lib/leetcode.js`'s `history` op (session regex-validated; `leetcodeHeaders` fetches a csrftoken via anonymous GET and sends the `csrftoken`/`LEETCODE_SESSION` cookie pair + `x-csrftoken`) pages `userProgressQuestionList` (100/page; query shape matches JacobLinCool/LeetCode-Query and was schema-validated live, but **not yet run with a real session**). The cookie is never stored or logged. `userStatus.username` must match the track's username. Each problem → one `hist:<slug>` log at `lastSubmittedAt` (solved or failed), skipping slugs that already have a LeetCode solve logged. History never enters the re-solve queue. Two mastery changes make this safe: accepted problem solves never decay below `BASELINE_WEIGHT` (otherwise importing history would *lower* levels, since the baseline subtracts dated logs), and `baselineForTopic` subtracts *distinct accepted* problems, not every LeetCode log. `fetchLearning` now pages items/logs with `.range()`, because PostgREST caps responses at 1,000 rows, so the old `.limit(2000)` silently returned 1,000.
- **Company prep (2026-10-05)**: `lib/learning/companyProblems.js` (pure) + `useCompanyPrep.js` read the public `liquidslr/leetcode-company-wise-problems` dataset (LeetCode company tags are Premium-only). The folder index comes through `/gh-api` and the CSVs straight from `raw.githubusercontent.com`, which is now in CSP `connect-src`. Both are cached a week per browser. Its time windows aren't cumulative: the code takes Three Months, then Six Months, then All, stopping at the first with ≥15 problems. Companies = Pipeline apps at interview stage or OA due ≤21d for this track + `track.config.prepCompanies` (pinned). `companyTopicDemand` feeds `rankGaps` (+1.5 × the topic's share of the company's frequency mass, reason "N% of X's asked problems"); generic tags (`array`, `string`, `math`…) only count when no specific tag matches. `CompanyPrepWidget` ('company', `lcOnly` → auto-shown on existing LeetCode tracks) shows frequency-weighted coverage, which topics the company leans on vs. your level, and the most-asked unsolved problems. Off-bank problems logged manually now get real LeetCode tags via `resolveQuestionMeta`.
- **Bulk practice import (2026-10-10)** — Learn header → **Import** (`components/learning/ImportPracticeModal.jsx`, pure logic in `lib/learning/practiceImport.js`, `test/practiceImport.test.js`). For every track, since almost no prep platform has an export/API: **Spreadsheet** (CSV file or rows pasted from Sheets/Excel, no AI key; headers matched by alias; a tab-separated header splits on tabs only, because `splitCsvLine` also splits on commas; "Template for <track>" downloads a CSV pre-filled with the track's topic names), **Paste** (text → `aiJSON` STANDARD via `lib/ai.js`), **Screenshot** (Claude Sonnet vision, always Claude like `AddToCalendarModal`; `downscaleImage` now lives in `lib/image.js`). AI output goes through `validatePracticeItems`: kinds and outcomes are forced onto allowed sets, topic names map to real topic ids or surface as `unmatchedTopic`, and undated or future items are dropped. Scores normalize to the 0–5 scale `mastery.js` reads (`4/5`, `82%`, `7/10`, bare numbers). Drafts are editable, then `useLearning.importPractice` → `draftsToLogs` (source `import`, `externalRef` = hash of date+kind+title+topics plus an occurrence index for identical same-day rows) → `importLearningLogs` in 200-row chunks. Re-importing is a no-op ("N already there"), and new rows are merged into local state without a reload. No migration, no new API file. Verified live for CSV (import, then a re-import that wrote 0 rows); the Paste/Screenshot model calls were not run live (no AI key available to the test account), only their validators.
- **Re-solve queue** (`lib/learning/review.js`, `ts-fsrs`): a problem logged hinted/failed (or low-confidence) gets FSRS state on `learning_items.srs`/`due_at`; never scheduled sooner than tomorrow; confident first solves never enter.
- **AI** (`lib/learning/coach.js`, via `lib/ai.js`, BYOK, fail-soft): weekly study plan (MINI, cached in `user_settings.learning_plan:<trackId>`; problem picks restricted to `lib/learning/problemBank.js` and validated after the call — can't invent problems/links); explain-back grader (STANDARD) returns covered/missed rubric points + one Socratic hint, **never a model answer**, and logs a scored `explain_back` entry — the main evidence source for concept topics. Validators unit-tested; the live AI calls were not exercised in verification (no BYOK key on the test account).

Also in the `/demo` nav with seeded data (`demoData.js`'s `buildDemoLearning`).
